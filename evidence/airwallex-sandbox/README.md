# Airwallex sandbox smoke evidence

Generated by `bun scripts/airwallex-sandbox-smoke.ts` against `api-demo.airwallex.com` (sandbox, fake money).

What the run proves:

1. `prepare` derives a deterministic `request_id` from the Railguard intent id.
2. `create` sends one real sandbox transfer (`POST /api/v1/transfers/create`) and records the transfer id.
3. A second `execute` for the same intent is blocked locally (fail closed, no second create).
4. Replaying the same `request_id` at Airwallex returns `duplicate_request_id`, so no second transfer exists.
5. Reconcile by `request_id` (`GET /api/v1/transfers?request_id=`) finds the transfer and maps its status.

The manifest records no credentials or tokens. The beneficiary id is stored only as a short SHA-256 prefix.
